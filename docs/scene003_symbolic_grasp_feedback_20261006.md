# 象征性抓取与实时 reasoning graph 反馈

## 用户要求

物品必须经过机械臂接近、下探、闭爪后跟随实际夹爪，到达目标后张爪放下。
遮挡或不可达导致的失败必须反馈给高层，高层根据当前视觉调整图及下一步动作。
低层可以读取仿真几何辅助执行；高层不读取仿真物体坐标。

## 实现

- `script/symbolic_grasp_execution.py`：数值 IK 驱动真实机器人关节，实际指端到达抓取点并闭爪后建立理想跟随约束。物品位置来自实际指端，朝向随腕部转动；张爪后解除。失败不通过设置目标物位姿补完，也不瞬移回滚。
- 抓取前检查上方遮挡物，输出源物体 ID、遮挡物 ID、失败类别与阶段。这里使用低层几何，但输出给模型的是执行反馈，不是世界坐标。
- 选臂检查源点、抬升、目标上方与放下位置的可达性。IK 加入另一机械臂的间距约束，保留路径预检和运行时间距检查。
- `script/symbolic_feedback.py`：每次只执行一条边；动作完成后用实时 RGB 更新 scene graph、定位节点。观察匹配时复用剩余图；失败或不匹配时记录执行证据，调用 `update_target_conditioned_scene` 修复或重建图。
- 不要求初始图已经包含完整 GOAL 路径。若完整路径搜索失败但当前节点存在未失效的候选动作，可执行一条后继续观测。
- `high_level_planner/evidence.py`：修复反馈被过滤的问题。原过滤器只留下异常类型，模型无法知道遮挡物是谁。现在保留经过类型检查的失败类别、阶段、物体 ID、遮挡物 ID 列表和动作状态布尔值，继续丢弃仿真坐标及其他低层诊断。
- `high_level_planner/planner/planner.py`：同一遮挡状态下禁止重复失败动作；遮挡物在后续视觉／候选节点中改变位置后，允许重新检查抓取。视觉后置条件不匹配不再等价于永久禁用该动作。
- 若搬运失败时仍持物，尝试用机器人反向执行已走过的搬运路径、返回抓取点后张爪，再观察并重规划；无法安全返回则停止新抓取。实际运行时双臂违规仍硬停止。

## 验证边界

这是高层规划与可见抓取动作链验证。理想抓持允许保持物品直立，物品采用运动学刚体，物品碰撞关闭，因此不代表真实摩擦接触抓取成功。抓取点遮挡由显式低层检查拒绝，机器人双臂安全检查仍有效。

未能读取可靠视觉时，不继续旧动作序列；重规划失败和仍持物无法恢复也会明确停止。
录像始终保留本轮已经执行的全过程，不把截断视频标成完整到达终态的验证。

### 已确认的外部反馈证据

v169 的 `model_audit/request_0001.json` 已包含 `failure_category=grasp_occluded`、
`blocking_object_ids=["cup_sam3"]`、`phase=before_grasp` 和 `object_moved=false`。
`response_0001.json` 的第一个候选改为移动杯子到右上方，并明确说明这会解除书的遮挡。
这验证了“执行失败 → 语义反馈 → 外部模型调整候选动作”的真实调用链。
它本身不等价于最终布局或整轮执行已经通过；应以动态 trace 的最终状态为准。

### 整合修正

v171 实际采用了修复图的移杯动作，证明并非只打印模型建议。杯子下降时受显示器
碰撞体阻挡，随后机械臂沿已执行路径返回抓取处并张爪释放，第二次失败也进入高层反馈。
象征性模式现将固定显示器纳入与其他道具相同的碰撞处理；独立杯子测试成功，放置误差
约 2.3 mm。这仍属于理想抓取验证，不是避开显示器碰撞的物理规划验证。

另修复两处图衔接：每次视觉更新后保留验证模式；允许执行可用的局部修复图，
不因缺少整条 GOAL 路径而丢弃。反馈规划采用 4 层、8 状态、最多 4 次局部修复扩展，
已有局部图执行完后从最新观测继续扩展。该限制控制每轮计算规模，不固定场景坐标、
物品顺序或缓冲位置。

### 实时视觉的一致性

v172 在 8 次动作尝试后因视觉身份解析不确定停止。新增已完成搬运的身份提示，
结合唯一类别、前后外观相似度及尺寸一致性匹配跨区域移动的物品。新图的位置仍来自
检测结果；多实例或外观不一致时不强制合并。动作提示在标签校正前传入，也在图合并前
进行保守复核，避免杯子搬走后同时保留旧杯子并新增 `cup_sam3_1`。

目标图的 `yaw_semantics=visual_delta_from_initial_reference_degrees` 之前被低层
误当世界绝对角度。现在低层根据本轮初始朝向转换该相对旋转；高层每次用初始／当前
SAM 轮廓测量视觉旋转，和目标图采用相同语义，不能使用机械臂命令值代替视觉观测。
