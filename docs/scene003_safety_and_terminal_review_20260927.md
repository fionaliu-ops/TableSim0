## 1. 为什么原先达不到图片终态

下表按可核查的现象、原因和修改整理。问题分别来自目标定义、作业安排、运动可达性、姿态控制和运行环境，不能全部归因于语言模型。

| 因素 | 现象或证据 | 修改及作用 |
|---|---|---|
| 成功定义与图片不同 | 原有区域谓词满足，不代表逐物体与图片对齐 | 新增图片目标，检查位置、投影位置、朝向、倾斜和书本支撑；旧谓词仅保留为诊断 |
| 请求目标与实际执行不一致 | 旧执行器存在按场景替换坐标的分支；缓冲位置容易与终态混淆 | 删除静默替换，显式安排缓冲和最终位置；最后再次归位手机 |
| 中央工作区争用 | 右臂持书时左臂进入下方整理文件夹，腕部及夹爪容易过近；早期轨迹曾测得 0.059 m，小于带余量的 0.060 m 要求 | 右臂持书退出左侧工作区，左臂整理后向外撤离，右臂再放书；执行前和运行时均验距 |
| 物品阻挡通道 | 诊断中出现接触手机、杯子侧抓接触鼠标、鼠标目标受杯子阻挡 | 手机、键盘、鼠标临时避让与二次避让；杯子采用桌面支撑交接 |
| 显示器整体投影不适合低位规划 | 屏幕整体二维投影可能误判低位目标被占用；高位携杯又确实可能撞屏幕 | 使用实际高度区间的碰撞几何截面；杯子先在屏幕前降低，再低位送入；保留实际接触检查 |
| 抓取方向与执行臂不适合紧凑终态 | 订书机下降曾接触书本或文件夹；右臂到手机最终位置 IK 失败 | 订书机由左臂垂直下探；手机最终由左臂放置；杯子调整侧抓方向 |
| 只纠正偏航，不纠正倾斜 | 书本朝向正确仍可能斜放 | 用实测位姿分段旋转，同时恢复水平姿态；偏航正确但倾斜过大仍继续修正 |
| 等待与归位没有充分确认实际状态 | 持书等待高度漂移，空闲臂残余运动影响下一步 | 持书位置反馈校正；交接前等待关节速度收敛 |
| 单一接近或归位路径不可解 | full_v2 归位出现 FINETUNE_TRAJOPT_FAIL；full_v3 后段右臂接近找不到分离路径 | 增加完整预检的高位分段、本侧前方空手中转路径；full_v4 随后通过，但不据此宣称所有随机求解分支都必然成功 |
| 感知与运行环境故障 | 订书机漏检；早期相机外参为 3×4、图接口错误、SAM3 不可用 | 补齐齐次矩阵，修正接口，恢复本机服务；漏检对象显式使用 sim_* 标识，承认仿真真值介入 |

## 3. 我在哪些部分进行了干预

### 3.1 目标解释：人工标注和三维约束

我从确认图片读取七个物体的归一化中心，并指定文件夹、手机、键盘、鼠标偏航为 0°，书本与订书机为 −90°。用当前相机内外参、桌高和仿真物体尺寸，将中心反投影至对应高度平面。书本与文件夹共享物理 XY 中心，避免透视和厚度产生的可见中心差异破坏堆叠。

因此，这是**指定图片下的人工目标约束**，不是模型自动恢复完整三维终态。更换图片必须重新标注和验证。目标图与仿真资产的外观、比例仍有差异，不以像素完全一致为成功标准。

### 3.2 高层顺序：明确安排避让与归位

本地完整验证执行显式计划，没有调用外部语言模型决定顺序。外部闭环入口也加入 constrained_scene003_action：模型建议会保留记录，但实际动作可被规则替换。这强于单纯拒绝不安全动作，后续成功不能全部归功于模型。

坐标是世界桌面 XY，单位 m；最终目标来自图片标注，允许有限的邻近位置搜索。

| 步骤 | 动作 | 目的 |
|---|---|---|
| 1 | 手机 → (−0.045, −0.240) | 临时避让键盘抓取 |
| 2 | 键盘 → (0.220, −0.200) | 让出书本操作空间 |
| 3 | 鼠标 → (0.280, −0.100) | 清理杯子交接区 |
| 4 | 左臂将杯子放到 (0.180, −0.050) | 桌面支撑交接；退出后右臂重抓 |
| 5 | 右臂将杯子送至图片目标 | 屏幕前降低、低位插入 |
| 6 | 手机 → (0.080, −0.230) | 第二次临时避让 |
| 7 | 右臂持书等待；左臂整理文件夹；右臂旋转并叠放书本 | 分离工作区、对齐支撑与姿态 |
| 8 | 鼠标 → (0.300, −0.030) | 让出键盘抓取通道 |
| 9 | 键盘 → 图片目标 | 最终归位 |
| 10 | 鼠标 → 图片目标 | 最终归位 |
| 11 | 左臂将订书机 → 图片目标 | 垂直接近，旋转至 −90° |
| 12 | 左臂将手机 → 图片目标 | 离开缓冲区，完成布局 |

原始记录第 6 步沿用历史 phase: final 名称，但实际坐标仍是缓冲位；真正手机终态是第 12 步。此处按实际目标解释，没有改写原始记录。

### 3.3 几何与动作：使用仿真真值，指定策略与容差

我使用了物体尺寸、实际位姿、机器人关节和碰撞几何；SAM3 漏检对象通过显式仿真 ID 补齐。这不是无特权状态的纯视觉系统。

我指定了执行臂、抓取方向、持书等待位、外侧停靠位与杯子送入方式。最终位置搜索上限是 0.024 m，验收容差是 0.025 m。紧凑布局的局部物体留白采用较小值，订书机保留更大的前侧间隔；这些是规划参数干预。双臂运行间距阈值没有为通过测试而缩小。

### 3.4 仿真物理：保留跟随、位姿校正和支撑稳定辅助

**现有执行模式是 kinematic_follow。** 抓取后，物体按末端到物体的相对变换跟随机械臂，并非完全依靠接触力和摩擦。

文件夹整理采用左腕带动薄物体转动和平移，结束后通过 set_pose 保持桌面支撑高度与水平姿态。整理文件夹时持书位姿临时固定，释放后的书本也采用位姿固定稳定薄物体堆叠。释放与撤退阶段保留位姿冻结/校正：一般放置会将物体 XY 写为选定释放位置，堆叠还会设置支撑高度，并保持规划的物体朝向。因此最终误差包含显式位姿辅助的效果，不全是机械臂接触控制的精度。这些辅助降低了物理抖动，但不能据此声称已验证真实抓取和支撑力学。

下降等操作仍存在针对书本的特定接触例外。本报告只声称记录中的**双臂相互接触为零**，不扩大成所有机器人—物体接触都为零。图片目标模式不再在下降失败时吞掉异常并近似释放；旧兼容模式中的近似释放分支仍保留。

### 3.5 调试：后半段恢复与最终完整验收分开

调试用过 prefix fixture 恢复已记录物体位姿，再执行后半段。suffix_v17 通过只能证明相应恢复状态下的后半段通过。

最终 full_v4 从原始场景开始，没有 prefix fixture，也没有拼接前后段；live_sam3_called 为 true，12 步全部 executed。本机 SAM3 曾因 GPU 状态异常重启，最终运行确实调用了本机感知。
