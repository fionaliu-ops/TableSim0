## 如何绕过低层阻塞

新增 [`script/object_motion_validation.py`](../script/object_motion_validation.py) 和
`--graph-validation --object-motion-validation` 入口。保持外部模型给出的动作顺序和目标参数，
低层使用当前仿真相机标定、物体高度与支撑高度，将图像位置转换为执行位置。
每个动作依次连续抬升、平移／旋转、下降；转移高度从当前物品高度计算，不使用旧场景缓冲坐标。

物品按每个仿真步的插值位姿更新，本轮实测最大单步平移 **0.480 mm**。
不存在失败后重置位置、直接跳到终点的分支。机械臂保持原位，因此该模式不验证
真实夹取、IK、抓取摩擦或中间支撑力学。录像 manifest 明确标记
`has_robot_control_steps=false`、`has_object_motion_steps=true`。

高层仍使用视觉场景图，仿真真值只在低层执行器内用于几何与坐标转换。
视觉观察器只收到相机图像，不用实际物品坐标替代视觉检测，也不把期望节点当作观察结果。

## 完整视频暴露的剩余问题

1. 标签／身份关联仍不稳定，尤其在物品暂移、旋转和重叠后；后续多次出现
   `Visual identity unresolved`，部分节点不能从新相机图像获得可信定位。
2. 初始视觉图没有订书机，目标图和动作链也未覆盖它；不能把其余物品归位理解成完整桌面终态。
3. 图像朝向与世界偏航的执行语义仍需统一。实际最终书本与文件夹朝向和目标图不一致，
   这不是此前“文件夹必须完全可见”约束造成的。该可见性错误已经修复，本轮图也成功包含 GOAL。

另外修正了结果报告的边界：最终视觉更新失败时，不能用上一次成功观察冒充最终观察。
v164 的原始 trace 保留当时输出，其 `final_visual_goal_report` 对应最后一次成功场景观察，
不是第 11 步末帧；`verification_summary.json` 已明确注明。修正后的代码在最终观察失败时
将该报告置空，并输出 `final_visual_observation_available=false`。
